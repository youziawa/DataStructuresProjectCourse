## 1. 关键字和统计

`file_cmp` 有两种关键字。

- `KEY_NAME`：按文件名字节序比较，和 `strcmp` 一致。
- `KEY_SIZE`：只比较大小。大小相等时返回 0，不再用名字打破平局。这样稳定排序才能保留原来的先后次序。

返回值小于 0、等于 0、大于 0，分别表示第一条应排在前面、关键字相等、第一条应排在后面。

每次关键字比较记入 `OpStat.compares`，每次元素赋值记入 `OpStat.moves`。不关心统计时，指针可以传空。检查“表是否有序”的扫描不记入查找比较次数，避免把预处理算进查找。

稳定性的结论：直接插入、折半插入、冒泡在关键字相等时不交换位置，稳定。希尔排序和快速排序会把相等元素交换到不相邻的位置，不稳定。

## 2. 折半查找

函数 `bin_search`。表必须已经按文件名升序，否则返回 -2，避免在无序表上给出一个碰巧相等、却不能代表正确区间的下标。

区间是闭区间 \([low, high]\)，一开始是 \([0, n-1]\)。

1. 中点取 `mid = low + (high - low) / 2`。写成减法是为了避免 `low + high` 在下标很大时溢出。
2. `data[mid]` 与目标相等，返回 `mid`。
3. 中间元素比目标小，目标只可能在右半，`low = mid + 1`。
4. 中间元素比目标大，目标只可能在左半，`high = mid - 1`。
5. `low > high` 时失败，返回 -1。

每一次循环记 1 次比较。最坏比较次数是 \(\lfloor \log_2 n \rfloor + 1\)。成功时的平均比较次数大约是 \(\log_2(n+1) - 1\)。比较过程对应一棵判定树，树高是对数。额外空间 \(O(1)\)。

链表不能 \(O(1)\) 取到中点，所以折半查找只写在顺序表上。这句话和成员 2 一起讲：成员 2 说明链表的存储，本成员说明查找算法为什么依赖随机访问。

## 3. 分块查找

函数 `block_search`。表同样必须按文件名升序，否则返回 -2。块长为 \(s\)，最后一块可以不满。块数 \(b = \lceil n/s \rceil\)。

因为整表有序，第 \(i\) 块的最大键就是这块最后一个元素，不必再另建一个索引数组。查找步骤：

1. 按块的顺序，用目标与块最大值比较。
2. 找到第一个“目标小于等于块最大值”的块。目标若存在，只可能在这块。
3. 在这块内部从头到尾顺序查找。
4. 这块里没有就失败，不再看后面的块。后面的块最小值至少不小于本块最大值，目标更不可能出现在后面。

平均比较次数大约是 \((b+s)/2\)：块间大约看 \(b/2\) 块，块内大约看 \(s/2\) 个元素。\(s\) 取在 \(\sqrt n\) 附近时，平均代价是 \(O(\sqrt n)\)，介于顺序查找的 \(O(n)\) 和折半查找的 \(O(\log n)\) 之间。若把每块最大值单独存成索引表，额外空间是 \(O(b)\)。本实现索引就取原表里的元素，额外空间是 \(O(1)\)。

## 4. 链地址法散列表

### 散列函数

`hash_string` 使用 djb2。初值 5381，每读一个字节做

\[
h = h \times 33 + c
\]

再用桶数取余，得到桶号。运算使用无符号整数，溢出按字长回绕，结果有定义。桶数由调用方指定，实验里用质数 17 或 127。传入的桶数小于 1 时，改用 211。

### 冲突处理

每个桶是一条单链表，链结点是手写的 `HashNode`，不用库容器。插入时把新结点放到链头：新结点的 `next` 指向桶里原来的链，桶再指向新结点。插入时间 \(O(1)\)。后插入的同名记录会先被找到。

同名允许共存。不同目录可以各有一份 `习题.pdf`，它们落在同一个桶的同一条链上。`hash_search` 返回链上第一条。`hash_search_all` 把这条链上名字相等的记录全部收进顺序表。比较次数只统计这条链上的关键字比较，不是把所有桶都扫一遍。

### 复杂度

设元素个数为 \(n\)，桶数为 \(m\)，装填因子 \(\alpha = n/m\)。链地址并且采用头插时，成功查找的平均比较次数大约是 \(1 + \alpha/2\)，可以看成平均 \(O(1)\)。全部关键字落进同一个桶时，查找退化成扫描一条长度为 \(n\) 的链表，最坏 \(O(n)\)。空间是桶数组加上全部链结点，即 \(O(n+m)\)。

菜单里的查找对照在同一张已经按文件名排序的表上进行：顺序查找的成功平均接近 \((n+1)/2\)，折半查找是对数，分块查找介于两者之间，散列在装填因子不大时接近常数。失败的顺序查找应比较 \(n\) 次。

## 5. 直接插入排序

`a[0 .. i-1]` 已经有序。把 `a[i]` 取出，从 \(i-1\) 向左扫描，比它大的元素向右移一格，空出插入位置。

- 最好情况是输入已经有序。每趟只比较 1 次就发现左边并不更大，比较次数 \(n-1\)，移动次数 \(2(n-1)\)（取出一次、放回一次），时间 \(O(n)\)。
- 最坏情况是逆序。每一趟都要把前面的元素全部右移，比较和移动都是 \(O(n^2)\)。
- 平均也是 \(O(n^2)\)。
- 额外空间 \(O(1)\)，只有一个临时元素。
- 关键字相等时停止左移，新元素留在相等元素后面，所以稳定。

按大小排序时，记录 `(a,1)、(b,2)、(c,1)` 的结果是 `a, c, b`。a 和 c 大小相同，a 仍在 c 前面。

## 6. 折半插入排序

查找插入位置改为折半，元素移动仍和直接插入一样。

循环结束时 `low` 就是插入位置。关键字相等时走“不大于就到右半边”，即 `low = mid + 1`，新元素插入到已有相等元素的后面，因此稳定。

- 比较次数大约 \(O(n \log n)\)，因为每一趟在长度为 \(i\) 的有序段里折半。
- 移动次数不变。逆序时仍要把大段元素右移，最坏 \(O(n^2)\)。
- 已经有序时没有元素需要右移，移动仍是 \(2(n-1)\)，但比较次数多于 \(n-1\)。
- 额外空间 \(O(1)\)。

折半插入减少的是比较，不是移动。数据移动很贵时，它不会比直接插入快一个数量级。

## 7. 希尔排序

增量序列是 \(n/2,\ n/4,\ \ldots,\ 1\)。对每个增量 `gap`，把相距 `gap` 的元素做一趟插入。最后一趟增量一定是 1，这时等价于直接插入，结果才保证整体有序。

增量较大时，一个元素可以一次跨过许多位置，逆序比相邻插入消除得更早，平均情况通常好于 \(O(n^2)\)。这组简单增量的最坏情况仍可能达到 \(O(n^2)\)。额外空间 \(O(1)\)。分组插入会越过原来相邻的相等元素，不稳定。

## 8. 冒泡排序

相邻两个元素逆序就交换，一趟把当前最大的元素沉到末尾。第 \(i\) 趟之后，末尾 \(i\) 个元素已经就位，内层不再看它们。

若某一趟没有发生交换，说明已经有序，提前结束。

- 最好：输入有序，只做一趟，比较 \(n-1\) 次，时间 \(O(n)\)。
- 最坏：逆序。第 \(i\) 趟比较 \(n-1-i\) 次，总比较次数 \(n(n-1)/2\)，时间 \(O(n^2)\)。
- 一次交换是 3 次赋值：取出、前移、放回。
- 只在“大于”时交换，相等元素保持原顺序，稳定。
- 额外空间 \(O(1)\)。

\(n=5\) 且大小为 `5,4,3,2,1` 时，比较次数应为 10，排序后名字次序与原来相反。

## 9. 快速排序

枢轴取当前区间最左端元素，先存到临时变量里，左端位置视为空位。然后双向扫描：

1. 右指针向左找比枢轴小的元素，放到左边的空位，空位转移到右边。
2. 左指针向右找比枢轴大的元素，放到右边的空位，空位转移到左边。
3. 两个指针相遇的位置就是枢轴的最终下标。
4. 左边都不大于枢轴，右边都不小于枢轴。
5. 递归处理左段和右段。区间长度小于 2 时返回。

平均情况下划分比较均匀，时间 \(O(n \log n)\)，递归深度平均 \(O(\log n)\)。枢轴固定取最左端时，输入已经有序会使一边为空，每一层只减少一个元素，比较次数变成 \(O(n^2)\)，递归深度变成 \(O(n)\)。元素可能被交换到很远的位置，相等关键字的相对次序不保留，不稳定。

课程数据的规模不大，递归深度可以接受。讲复杂度时要同时说出平均和这个最坏情况，不能只写 \(O(n \log n)\)。

## 10. 对照实验怎么读

菜单 12 用固定种子生成数据，每次运行的结果相同，报告里可以引用这些数字。

\(n=60\) 这一组用来看增长趋势。小数据那一组用来看排序结果是否正确、稳定排序是否保住了原来的次序。

## 12. 建议准备的测试

- 无序表上折半查找、分块查找都返回 -2。
- 有序的 `a` 到 `g`，折半能找到 `d`，分块块长为 3 时能找到最后一个 `g`，找不到时返回 -1。

- 五种排序对唯一名字的结果都是 `a,b,c`。
- 直接插入、折半插入、冒泡按大小排序后，`(a,1)、(b,2)、(c,1)` 变成 `a,c,b`。
- 已序输入上，直接插入比较 \(n-1\) 次；逆序输入上，冒泡比较 \(n(n-1)/2\) 次。
- 20 组随机大小数据，五种排序之后都非降序。
- 能口述快速排序在已序输入上为什么变慢，以及折半插入为什么比较变少、移动没变少。
